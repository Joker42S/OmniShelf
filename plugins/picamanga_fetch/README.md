# 哔咔收藏夹抓取（`picamanga_fetch`）

把**自己哔咔收藏夹里的漫画**同步下来，存成可以直接导入的 JSON，
并（可选）用内置 importer **`picamanga`** 直接入库。

这个插件：

* 抓取/同步用的是随插件分发的一份 **picamanga 工具包**（`plugins/picamanga_fetch/picamanga/`，
  由外部哔咔备份工具重构而来，见 `VENDOR.md`）——插件只负责表单、进度、落盘和导入；
* **接口地址、token、邮箱、同步方式、排序、翻页参数**都记在 `plugins_data/picamanga_fetch/config.toml`；
* **增量 / 全量**两种同步：增量日常一两次请求就够，全量能发现老条目的变化和取消收藏；
* 抓完**一键导入**（走宿主的 `import` 接口，和上传页/CLI 完全同一条链路）；
* 有进度条（实时显示翻到第几页）、同步报告和本地文件列表。

## 用起来

网页：顶部导航 **插件** → **哔咔收藏夹抓取** → `/plugins/picamanga_fetch`

1. **接口地址**默认 `https://picaapi.picacomic.com`，一般不用改；
2. **认证**二选一：
   * 粘 **token**——抓包 App/网页的请求头 `authorization: <token>`，复制值粘进来
     （带上 `Bearer` 也没关系，会自己去掉）；
   * 没有令牌就勾开下面那栏，填**邮箱 + 口令**，插件登录换一个令牌
     （换到的令牌会留下，口令不会）；
3. 第一次先跑一次**全量**，把整个收藏夹落下来；以后用**增量**就很快；
4. 本机直连接口不通的话，填上**代理**（见下面「连不通时：代理」那一节）；
5. 点 **同步并导入**。

命令行同理：

```bash
# 第一次：全量同步并导入
omnishelf plugin picamanga_fetch fetch_import --token <登录令牌> --mode full

# 日常：增量（默认），只翻到上次的位置——令牌已经在配置里了，不用再传
omnishelf plugin picamanga_fetch fetch_import

# 只同步不入库
omnishelf plugin picamanga_fetch fetch_import --dry-run

# 用邮箱口令登录（口令会留在 shell 历史里，介意就用 --token）
omnishelf plugin picamanga_fetch fetch_import --email <账号邮箱> --password <口令>

# 直连不通，走本地代理
omnishelf plugin picamanga_fetch fetch_import --proxy http://127.0.0.1:10809
```

## 关于认证

* **token 优先**：令牌会存进本地配置，下次直接复用；用邮箱口令登录成功的那一刻就当场存下来，
  不用等这次同步跑完（同步中途失败也不白登一次）。
* **表单里令牌留空 = 用配置里存着的那个**，不是「把它忘掉」：所以第一次口令登录之后，
  直接再点一次同步就行，不会被要求重新认证。要换账号就粘一个新令牌。
* **令牌过期**（接口回 401，或业务错误码 `1005`/`1008`）时，这次填了邮箱和口令就自动重新登录再同步。
* **口令不落盘、不进日志、不回显**，只在本次同步里用一次。
* 哔咔的每个请求都要带一套 HMAC-SHA256 签名头，值是官方 App 内置的那组常量，
  签名用的路径**要去掉前导斜杠**——带着 `/` 去签，服务端不报错，只回一个假的
  `{"code":200}` 空响应。这些都在工具包里处理好了。

## 连不通时：代理

哔咔的接口域名在不少网络环境里直连不通，所以表单里有一栏**代理**，命令行有 `--proxy`，
配置里有 `proxy`：

* 填法：`http://127.0.0.1:10809`（HTTP/HTTPS 代理）。只写 `IP:端口` 会按 HTTP 代理补上协议；
  SOCKS 端口**要自己写全** `socks5://127.0.0.1:10808`（补协议只会补成 `http://`，写错方向）；
* 填了就**这次同步的每个请求都只走它**（包括登录那一次），而且会顶掉系统环境变量里那份代理，
  不会半路被换掉；报告会专门有一行写这次走的是哪条路；
* 留空 = 不在这里指定代理，这时 urllib 仍会认 `HTTPS_PROXY` 之类的环境变量，没设就是直连。
  所以「配置里存过一个代理、这次想直连」就把框清空再点同步（代理不是凭据，和令牌的留空语义不同）；
* 填了个认不出来的地址会当场拒绝并提示，不会悄悄换成直连跑一次——直连本来就不通，
  那样只能得到一句莫名其妙的失败；
* 代理地址会和其他连接项一起存进 `config.toml`（它不含凭据；口令照旧什么都不落）。
  代理不通时的报错会带上是哪个代理，好和「接口本身出错」区分开。

## 两种同步方式

| 想要 | 方式 |
| --- | --- |
| 日常刷新（快） | 增量 |
| 刷新老条目的字段、找出取消收藏的 | 全量 |

收藏夹接口按 `s=dd`（**收藏日期新到旧**）返回，所以新收藏排在最前面。但哔咔**不返回收藏时间**，
也没有任何「加入书架编号」能当水位线用，所以增量的停手条件是「**连续**命中若干条本地已有的收藏」
（默认 5 条）而不是「命中一条就停」——取消收藏后重新收藏会把那条老收藏刷回头部，
它后面紧跟的可能全是新收藏，命中一条就停会把这些全漏掉。

同步结束后还会校验一条不依赖编号的前提：远端总数涨了、这一轮却一条新收藏都没找到，
说明最新的收藏不在头部，此时自动改跑一遍全量并在报告里标出来，
**宁可多花几个请求也不静默漏数据**。

## 配置（`plugins_data/picamanga_fetch/config.toml`）

页面上「保存默认值」写入；**同步时接口地址 / 认证 / 方式 / 排序 / 翻页参数也会自动记住**。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `host` | `https://picaapi.picacomic.com` | 接口地址 |
| `token` | 空 | 登录令牌（**会存进本地配置**，和 Cookie 一个性质；表单留空就是用它） |
| `email` | 空 | 账号邮箱（**口令不在这个表里**，每次现填） |
| `mode` | `incremental` | 默认同步方式：`incremental` / `full` |
| `sort` | `dd` | 列表排序；增量只允许 `dd`（新到旧），别的取值只在**全量**下生效 |
| `delay` | `0.15` | 翻页间隔秒数 |
| `timeout` | `30` | 单次请求超时秒数 |
| `proxy` | 空 | 代理地址，如 `http://127.0.0.1:10809`；空 = 不在这里指定（直连，或跟随系统环境变量） |
| `include_raw` | `false` | 状态库里保留接口返回的全部字段（导入用不到，文件会大不少） |

单页 **20 条是服务端定死的**（实测 `limit` 参数被忽略），所以这里没有「每页条数」可调，
进度条的分母按「总数 ÷ 20」估算。

## 落盘与导入

都在 `plugins_data/picamanga_fetch/` 下：

* `picamanga_favorites.json`——**状态库**：扫描顺序（新收藏在前）、首次/最近见到、取消收藏标记都在里面，
  下次增量的连续命中判定靠它；
* `picamanga_import.json`——**导入文件**：只放还没取消收藏的条目，形状正好是 importer
  `picamanga` 认的那份导出格式（`{"items": [...]}`，每条 19 个字段）；
* `picamanga_fetch.meta.json`——上次同步的概况（页面列文件时只读这个小文件）。
  只留状态（同步方式、页码、条数、时间），逐页流水不写在这儿——它在宿主的
  `data/logs/plugins/picamanga_fetch.log`，浏览器里 `/logs` 实时看。

导入调的是 `ctx.host.import_file("picamanga", 导入文件)`，**判重靠漫画自己的编号**
（`comicId` → `external_ids.picamanga`），所以同一批重复导入只会「未变化」。
到 `/upload` 页选 importer `picamanga` 手动导入这个文件也可以（内容一模一样）。

书名 / 作者 / 题材（`categories` → 标签）/ 是否完结 / 话数 / 封面 / 热度都会带上。

## 已知边界（有意为之）

* 接口**不提供收藏时间**，也不给「最新话 / 源站更新时间 / 是否有新话」——这些要逐本再请求
  章节接口才知道。所以导入文件里这几项留空（入库时不写），代价是省掉几十倍请求；
  想要这些字段的话到 `/manga` 详情页手动补，或者以后加个逐本刷新的插件；
* 这个来源**没有 year / 评分 / 阅读状态**，入库后这三项是空的；
* **取消收藏的作品不会从库里删掉**——导入接口只新增/更新，不删；它们只在状态库里打个标记，
  也不会再进导入文件。只有**完整翻完且没有任何一页失败**时才会打这个标记；
* 增量只顺带刷新「翻到的那几页」里老条目的字段（爱心数、话数、封面），没翻到的不动——
  要整库刷新老字段就跑一次全量；
* 只提供 JSON（状态库 + 导入文件），不做 CSV / Markdown / Excel 的额外导出；
* 全量**没有单次页数上限**：一次点击就一路翻到末页，几千条的收藏夹也只是慢一点；
  报告会写这次停在什么原因上（`known-boundary` / `complete` / `fetch-error`）。
