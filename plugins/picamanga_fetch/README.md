# 哔咔收藏夹抓取（`picamanga_fetch`）

把自己在哔咔收藏夹中的**漫画**同步为可直接导入的 JSON，并可一键导入（内置 importer **`picamanga`**，与上传页/命令行走同一条导入链路）。接口的签名与请求细节由随插件分发的 picamanga 工具包处理，其来源与改动记录见 `VENDOR.md`。

功能要点：

* 增量 / 全量两种同步方式：增量日常一两次请求即可完成，全量能发现老条目的变化与取消收藏；
* 重复导入不会产生重复条目（按漫画自身的编号 `comicId` 判重，只会「未变化」）；
* 同步在后台运行，有进度条、同步报告与本地文件列表；
* 书名 / 作者 / 题材（`categories` → 标签）/ 是否完结 / 话数 / 封面 / 热度都会入库。

## 使用方法

网页：顶部导航 **插件** → **哔咔收藏夹抓取**（`/plugins/picamanga_fetch`）

1. **接口地址**默认 `https://picaapi.picacomic.com`，一般无需修改；
2. **认证**二选一：
   * 粘贴 **token**——App/网页请求头中的 `authorization: <token>`，复制值粘贴到此处（带 `Bearer` 前缀也可，会自动去除）；
   * 勾选认证栏，填写**邮箱 + 密码**，由插件登录换取令牌（换到的令牌会保存，密码不会）；
3. 第一次先跑一次**全量**，同步整个收藏夹；之后用**增量**即可；
4. 直连不通时填写**代理**（见下节）；
5. 点击**同步并导入**。

### 命令行

```bash
# 第一次：全量同步并导入
omnishelf plugin picamanga_fetch fetch_import --token <登录令牌> --mode full

# 日常：增量（默认），令牌已在配置中时无需再传
omnishelf plugin picamanga_fetch fetch_import

# 只同步不导入
omnishelf plugin picamanga_fetch fetch_import --dry-run

# 用邮箱密码登录（密码会留在 shell 历史里，长期使用建议令牌）
omnishelf plugin picamanga_fetch fetch_import --email <账号邮箱> --password <密码>

# 直连不通时走代理
omnishelf plugin picamanga_fetch fetch_import --proxy http://127.0.0.1:10809
```

## 认证说明

* **令牌优先**：登录成功后立即将令牌保存到本地配置，供下次直接复用；密码不落盘、不写入日志、不回显，仅在本次同步中使用。
* **表单中令牌留空**表示继续使用已保存的令牌：首次密码登录后直接再次同步即可，无需重新认证；更换账号时粘贴新令牌。
* **令牌过期**（接口返回 401 或业务错误码 `1005`/`1008`）时，若本次填写了邮箱和密码，会自动重新登录并继续同步。

## 代理

哔咔的接口域名在部分网络环境下无法直连，需要通过代理访问：

* 填写 `http://127.0.0.1:10809` 形式的地址；只写 `IP:端口` 按 HTTP 代理处理；SOCKS 需写全协议（`socks5://127.0.0.1:10808`）；
* 填写后，本次同步的**每个请求（包括登录）都只走该代理**，并覆盖系统环境变量中的代理设置；报告中会注明本次走的路径；
* 留空为不指定：系统环境变量（`HTTPS_PROXY` 等）中的代理设置仍然生效，未设置则直连；「配置中存有代理、本次想直连」时清空输入框即可；
* 填写的地址无法识别时会直接报错，不会静默改为直连；
* 代理地址会与其他连接项一起保存到 `config.toml`（不含凭据；密码仍不落盘）。代理连接失败时报错会注明所走的代理，便于区分是代理问题还是接口问题。

## 两种同步方式

| 目的 | 方式 |
| --- | --- | 
| 日常刷新（快） | 增量 |
| 刷新老条目的字段、找出取消收藏 | 全量 |

收藏夹接口按「收藏日期新到旧」返回，新收藏排在最前。但接口**不提供收藏时间**，也没有可作水位线的编号，因此增量的停止条件是「**连续**命中若干条本地已有的收藏」（默认 5 条）：取消收藏后重新收藏会把老条目刷回头部，其后可能紧跟新收藏，只命中一条就停会遗漏它们。同步结束后还会校验远端总数：若总数增加但未发现新收藏，会自动改为全量并在报告中标注，避免静默漏数据。

单页固定 20 条（由服务端决定），没有「每页条数」可调。

## 配置（`plugins_data/picamanga_fetch/config.toml`）

页面的「保存默认值」写入；同步时的接口地址、认证、方式、排序与翻页参数也会自动保存。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `host` | `https://picaapi.picacomic.com` | 接口地址 |
| `token` | 空 | 登录令牌（**会保存到本地配置**；表单留空即使用它） |
| `email` | 空 | 账号邮箱（**密码不落盘**，每次现填） |
| `mode` | `incremental` | 默认同步方式：`incremental` / `full` |
| `sort` | `dd` | 列表排序；增量只允许 `dd`（新到旧），其他取值仅在**全量**下生效 |
| `delay` | `0.15` | 翻页间隔秒数 |
| `timeout` | `30` | 单次请求超时秒数 |
| `proxy` | 空 | 代理地址，如 `http://127.0.0.1:10809`；留空为不指定 |
| `include_raw` | `false` | 状态库中保留接口返回的全部字段（导入用不到，文件会大不少） |

## 数据文件与导入

都在 `plugins_data/picamanga_fetch/` 下：

* `picamanga_favorites.json`——**状态库**：扫描顺序（新收藏在前）、首次/最近见到时间、取消收藏标记都在其中，下次增量的连续命中判定依赖它；
* `picamanga_import.json`——**导入文件**：仅包含未取消收藏的条目，格式即 importer `picamanga` 认的格式；
* `picamanga_fetch.meta.json`——上次同步的概况，页面列表使用；逐页明细记录在宿主运行日志（`/logs` 页）。

也可以到 `/upload` 页选择 importer `picamanga` 手动导入导入文件。

## 已知边界

* 接口**不提供收藏时间**，也没有「最新话 / 源站更新时间 / 是否有新话」（需要逐本请求章节接口才能得到），这几项留空，以节省几十倍的请求量；需要时可在 `/manga` 详情页手动补充；
* 该来源**没有 year / 评分 / 阅读状态**，导入后这三项为空；
* **取消收藏的作品不会从库中删除**（导入只新增/更新）：它们只在状态库中打标记，不再进入导入文件；仅在**完整翻完且没有任何一页失败**时才打标记；
* 增量只顺带刷新翻到的页中老条目的字段（爱心数、话数、封面），未翻到的不变；需要整库刷新时跑一次全量；
* 只提供 JSON（状态库 + 导入文件），不做其他格式的导出；
* 全量**没有单次页数上限**：一次点击会翻到末页，几千条的收藏夹只是耗时更长；报告会写明停止原因（`known-boundary` / `complete` / `fetch-error`）。
