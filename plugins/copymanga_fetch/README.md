# 拷贝漫画书架抓取（`copymanga_fetch`）

把自己在拷贝漫画书架上的**收藏**同步为可直接导入的 JSON，并可一键导入（内置 importer **`copymanga`**，与上传页/命令行走同一条导入链路）。抓取逻辑由随插件分发的 copymanga 工具包承担，其来源与本地改动记录见 `VENDOR.md`。

功能要点：

* 增量 / 全量两种同步方式：增量日常一两次请求即可完成，全量能发现老条目的变化与取消收藏；
* 只同步**漫画**（书架上的「動畫」在本库没有对应类型，不做抓取）；
* 重复导入不会产生重复条目（按漫画自身的编号 `comic_uuid` 判重，只会「未变化」）；
* 同步在后台运行，有进度条、同步报告与本地文件列表；
* 书名 / 作者 / 题材 / 连载状态 / 最新话 / 读到第几话 / 更新时间 / 封面 / 详情页地址都会入库。

## 使用方法

网页：顶部导航 **插件** → **拷贝漫画书架抓取**（`/plugins/copymanga_fetch`）

1. **站点地址**默认 `https://copy4000.com`，换镜像站时修改（可粘贴整条书架页地址，只取域名）；
2. 直连不通（超时）时，在**代理**中填写本地代理地址，如 `http://127.0.0.1:10809`（只写 `IP:端口` 也可，按 HTTP 代理处理）；
3. **认证**二选一：
   * 粘贴 **token**——浏览器开发者工具（F12）→ Network → 请求头中的 `Authorization: Token <token>`，或 Cookie 中的 `token` 值；
   * 勾选认证栏，填写**用户名 + 密码**，由插件登录换取令牌（换到的令牌会保存，密码不会）；
4. 第一次先跑一次**全量**，同步整个书架；之后用**增量**即可；
5. 点击**同步并导入**。

### 命令行

```bash
# 第一次：全量同步并导入
omnishelf plugin copymanga_fetch fetch_import --token <登录 token> --mode full

# 日常：增量（默认），令牌已在配置中时无需再传
omnishelf plugin copymanga_fetch fetch_import

# 只同步不导入
omnishelf plugin copymanga_fetch fetch_import --dry-run

# 用账号密码登录（密码会留在 shell 历史里，长期使用建议令牌）
omnishelf plugin copymanga_fetch fetch_import --username <账号> --password <密码>

# 直连不通时走代理
omnishelf plugin copymanga_fetch fetch_import --proxy http://127.0.0.1:10809
```

命令行的 `--proxy` 留空表示使用配置中保存的代理（与 `--host` / `--token` 口径一致）；页面上的代理输入框相反，**留空表示本次直连**。填写的代理地址无法识别时会直接报错，不会静默改为直连。

## 认证说明

* **令牌优先**：登录成功后立即将令牌保存到本地配置，供下次直接复用；密码不落盘、不写入日志、不回显，仅在本次同步中使用。
* **表单中令牌留空**表示继续使用已保存的令牌：首次密码登录后直接再次同步即可，无需重新认证；更换账号时粘贴新令牌。
* **令牌过期**（接口返回 401）时，若本次填写了用户名密码，会自动重新登录并继续同步。
* 代理地址支持 `http://用户:密码@主机:端口` 形式（需要认证的代理）：密码按凭据对待，日志、报告与元信息中只保留 `协议://主机:端口`；仅页面的代理输入框回显完整地址，以避免下次提交时丢失代理认证。

## 两种同步方式

| 目的 | 方式 |
| --- | --- |
| 日常刷新（快） | 增量 |
| 刷新老条目的字段、找出取消收藏 | 全量 |

接口默认按「加到書架時間降序」返回，新收藏排在最前：增量从头部翻起，整页未超过本地水位线即停止。同步过程中会实时校验排序，一旦发现排序口径变化，自动改为全量并在报告中标注，避免静默漏数据。

## 配置（`plugins_data/copymanga_fetch/config.toml`）

页面的「保存默认值」写入；同步时的站点地址、认证、方式与翻页参数也会自动保存。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `host` | `https://copy4000.com` | 站点地址 |
| `token` | 空 | 登录 token（**会保存到本地配置**；表单留空即使用它） |
| `username` | 空 | 账号（**密码不落盘**，每次现填） |
| `mode` | `incremental` | 默认同步方式：`incremental` / `full` |
| `page_size` | `100` | 每页条数 1~500，越大请求次数越少 |
| `delay` | `0.3` | 翻页间隔秒数 |
| `timeout` | `40` | 单次请求超时秒数 |
| `proxy` | 空 | 代理地址，如 `http://127.0.0.1:10809`；留空为不指定（见下） |
| `include_raw` | `false` | 状态库中保留接口返回的全部字段（导入用不到，文件会大不少） |

## 代理口径

* 填写后，本次同步的**所有请求（包括登录）都只走该代理**，并覆盖系统环境变量中的代理设置；中途不会自动改回直连。连接失败时错误信息会注明所走的代理。
* 留空为不指定：此时系统环境变量（`HTTP_PROXY` / `HTTPS_PROXY`）中的代理设置仍然生效，未设置则直连。
* 只写 `IP:端口` 按 HTTP 代理处理；SOCKS 代理需写全协议头（`socks5://127.0.0.1:10808`）。

## 数据文件与导入

都在 `plugins_data/copymanga_fetch/` 下：

* `copymanga_favorites.json`——**状态库**：水位线、首次/最近见到时间、取消收藏标记都在其中，下次增量依赖它；
* `copymanga_import.json`——**导入文件**：仅包含未取消收藏的条目，格式即 importer `copymanga` 认的格式；
* `copymanga_fetch.meta.json`——上次同步的概况，页面列表使用；逐页明细记录在宿主运行日志（`/logs` 页）。

也可以到 `/upload` 页选择 importer `copymanga` 手动导入导入文件。

## 已知边界

* **取消收藏的作品不会从库中删除**（导入只新增/更新）：它们只在状态库中打标记，不再进入导入文件；
* 增量只顺带刷新翻到的页中老条目的字段（最新话、人气等），未翻到的不变；需要整库刷新时跑一次全量；
* 只提供 JSON（状态库 + 导入文件），不做其他格式的导出；
* 全量**没有单次页数上限**：一次点击会翻到末页，几千条的书架只是耗时更长；报告会写明停止原因（`complete` / `known-boundary` / `watermark-reached`）。
