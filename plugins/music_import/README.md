# 本地音乐导入（`music_import`）

用**系统选择框**挑本地的音乐，读文件里的标签，存成清单 JSON 后用内置
importer **`music_files`** 直接入库。

这个插件：

* 页面上两个按钮，对应两种挑法——**选一个文件夹**（整个深度遍历）和
  **选多个文件**（只读选中的那几个）；
* 读标签和入库都走宿主接口（`audio` / `import`），**插件自己不解析标签、不碰数据库**；
* 和命令行 `omnishelf scan-music` 用的是**同一套扫描口径**（认哪些后缀、跳过哪些垃圾目录、
  没标签怎么兜底），所以两边扫出来的结果完全一致；
* 有进度条（实时显示读到第几个文件），扫完当场入库；
* 弹不出系统选择框的平台（非 macOS）会退化成手填路径，功能一样。

## 用起来

网页：顶部导航 **插件** → **本地音乐导入** → `/plugins/music_import`

1. 点 **选一个文件夹（深度扫描）**，或者 **选多个文件**——弹出的是访达自己的选择框；
2. 选完这一趟就开始跑，进度条每 0.5 秒刷新一次，切页面回来还能看到；
3. 扫完自动入库，页面上给出「新增 / 更新 / 跳过 / 未变化」；
4. 非 macOS 上没有访达对话框，直接在路径框里填（一行一个，目录和文件都能填）。

命令行做同样的事（不需要插件、也不弹选择框）：

```bash
# 只扫描，生成清单 JSON
omnishelf scan-music ~/Music

# 扫完直接入库
omnishelf scan-music ~/Music --import

# iTunes 导出的 XML 走另一个 importer
omnishelf import -i itunes_xml "iTunes Library.xml"
```

插件不再重复挂 `@cmd`：命令行那条路 `scan-music` 已经覆盖了，再造一个只是重复。

## 读哪些信息

只收集文件标签里这 11 项，别的（封面、流派、歌词、编码器…）一概不读：

标题 · 副标题 · 评分 · 备注 · 艺术家 · 专辑 · 专辑艺术家 · 年份 · 编号 · 时长 · 原始文件名

映射到库里：

| 标签 | 落到哪 |
| --- | --- |
| 标题 | `title`（没标签时拿文件名兜底：去掉后缀和开头的曲目号） |
| 艺术家 + 专辑艺术家 | `creators`（两个都当创作者，各自去重合并） |
| 专辑 / 艺术家原文 / 专辑艺术家原文 / 文件名 / 编号 / 时长 | `extra`（**原始字符串原样留着**，别被去重后的创作者列表顶掉） |
| 评分 | `rating`（只有 0–10 才认，越界就当没有） |
| 副标题 / 备注 / 年份 | 副标题进 `subtitle`、备注进 `notes`、年份是 `year` |

## 怎么算同一首歌

同一个来源（一个本地目录）里很容易有重复文件，判重看**内容**而不是文件名：

**标题相同 + 专辑相同 + `extra.artists` 相同 → 同一首。**

所以同一首歌换个码率、文件名改了、放在另一个文件夹里，导入第二次是「未变化」，
不会多出一条。反过来，翻唱（同曲名不同专辑/艺术家）和同名不同专辑的现场版都会各自留着。
标题里没有专辑和艺术家信息，所以只填标题、其它都空的两首无名曲会被认成同一首——
这种情况请把专辑或艺术家补进标签。

## 关于系统选择框

macOS 上用标准库的 `subprocess` 起 `osascript`（访达的 `choose folder` / `choose file`）：

* argv 是**固定**的，路径不经过 shell，没有注入问题；
* 用户按「取消」返回 `-128`，页面什么都不显示——那不是失败；
* 最多等 120 秒，走开一会儿也不会把请求线程挂死；
* 选中的路径会记进 `plugins_data/music_import/config.toml` 的 `last_paths`，下次打开页面还在。

**只读用户选的目录**，写盘只写在 `plugins_data/music_import/` 下面
（清单 `music_scan.json` 每次覆盖，只留最近一趟；结果另存一份在 `state.json`，
页面底部「上次扫描」显示的就是它）。

## 慢盘提醒

扫描放在后台线程里跑，几千首歌的库要几十秒到几分钟；外接盘（尤其是网络盘）更慢。
同一时间只跑一趟，进度条没走完再点会提示你先等它。
