# 本地音乐导入（`music_import`）

通过**系统选择框**挑选本地音乐文件，读取文件标签，保存为清单 JSON 后用内置 importer **`music_files`** 直接入库。

功能要点：

* 两种选择方式：**选一个文件夹**（深度遍历）和**选多个文件**（只读选中的文件）；
* 读取标签与导入都通过宿主接口（`audio` / `import`）完成，插件自身不解析标签、不直接操作数据库；
* 与命令行 `omnishelf scan-music` 使用**同一套扫描口径**（支持的后缀、跳过的目录、无标签时的处理），两边结果一致；
* 扫描在后台运行，有进度条，完成后自动入库；
* 无法弹出系统选择框的平台（非 macOS）可手动填写路径，功能相同。

## 使用方法

网页：顶部导航 **插件** → **本地音乐导入**（`/plugins/music_import`）

1. 点击**选一个文件夹（深度扫描）**或**选多个文件**，弹出系统选择框；
2. 选定后立即开始扫描，进度条每 0.5 秒刷新一次，期间可切换页面；
3. 扫描完成后自动入库，页面显示「新增 / 更新 / 跳过 / 未变化」；
4. 非 macOS 平台没有系统选择框，直接在路径框中填写（一行一个，目录和文件均可）。

命令行可完成同样的事（不需要插件，也不弹出选择框）：

```bash
# 只扫描，生成清单 JSON
omnishelf scan-music ~/Music

# 扫描后直接入库
omnishelf scan-music ~/Music --import

# iTunes 导出的 XML 走另一个 importer
omnishelf import -i itunes_xml "iTunes Library.xml"
```

## 读取哪些信息

只收集文件标签中的这 11 项，其余（封面、流派、歌词、编码器等）不读取：

标题 · 副标题 · 评分 · 备注 · 艺术家 · 专辑 · 专辑艺术家 · 年份 · 编号 · 时长 · 原始文件名

| 标签 | 入库位置 |
| --- | --- |
| 标题 | `title`（无标签时用文件名兜底：去掉后缀和开头的曲目号） |
| 艺术家 + 专辑艺术家 | `creators`（都作为创作者，各自去重后合并） |
| 专辑 / 艺术家原文 / 专辑艺术家原文 / 文件名 / 编号 / 时长 | `extra`（原始字符串原样保留） |
| 评分 | `rating`（只认 0–10，超出视为没有） |
| 副标题 / 备注 / 年份 | `subtitle` / `notes` / `year` |

## 如何判定同一首歌

同一来源目录中常有重复文件，判重依据是**内容**而非文件名：

**标题相同 + 专辑相同 + `extra.artists` 相同 → 同一首。**

因此同一首歌换码率、改文件名、放到其他文件夹后再次导入都会判为「未变化」，不会产生重复条目；翻唱（同曲名不同专辑/艺术家）和同名不同专辑的现场版则会各自保留。若某两首无名曲只有标题、其他都为空，会被认成同一首，建议为其补上专辑或艺术家标签。

## 关于系统选择框

* macOS 上使用系统标准对话框（访达的 `choose folder` / `choose file`）；
* 点击「取消」时页面不显示任何内容，这是正常行为，不是失败；
* 最多等待 120 秒；
* 选中的路径会记入 `plugins_data/music_import/config.toml`，下次打开页面仍然显示。

插件只读取所选目录，写入仅发生在 `plugins_data/music_import/` 下（清单 `music_scan.json` 每次覆盖，只保留最近一次；结果另存于 `state.json`，页面底部「上次扫描」显示的就是它）。

## 扫描耗时

扫描在后台线程中运行，几千首歌需要几十秒到几分钟，外接盘（尤其是网络盘）更慢。同一时间只运行一趟，进度条未走完时再次点击会提示先等待完成。
